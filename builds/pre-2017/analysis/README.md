# STALCRAFT Pre: пакет ранней загрузки ОФТ, октябрь 2017

Первичный статический разбор: 03.10.2026; восстановление байткода подтверждено 04.10.2026. Пользователь скачал `stalcraft_pre.rar` по найденному VK-посту и распаковал его в `E:\Stalcraft project\stalcraft_pre`. Исходный архив и распакованные файлы сохранены без изменений. После отдельного разрешения пользователя запускалась только диагностическая копия встроенной Java с `-version`; игра и вход в аккаунт не запускались.

## Продвижение восстановления после статического аудита

Снята память встроенной `jvm.dll`: доступны ранее отсутствовавшие на диске `.text`/`.rdata` и строки ClassLoader. Преобразование `MD5(имя + "2G5teW9TkteWdMSx")` воспроизводит все шесть известных `JLI_*` aliases. Вторая формула `MD5(внутренний путь + "nUHDjbS59e4wF8Pr")` сопоставляет 784 имени в `classes.jar`, 5 018 в `libs.jar`, 13 844 в JIMAGE. Имена и доказательства — [classname-inventory.md](<E:/Stalcraft project/builds/stalcraft-pre-vk-2017-candidate/analysis/classname-inventory.md>).

**Восстановлены все 30 715 защищённых классов:** 6 975 из `classes.jar`, 8 094 из `libs.jar`, 15 646 из JIMAGE. CBC, дополнительное преобразование ClassFileStream и перестановка JVM opcodes воспроизведены офлайн. Для каждого класса проверены структура, имя/salted MD5, нулевое заполнение; для всех методов — длины инструкций и границы переходов, включая switch/wide. Исходный runtime при этом не требуется запускать.

Готовые обычные class-only JAR находятся в `../recovered-bytecode/*-standard.jar`. Оба архива успешно декомпилированы CFR0.152: 5 519 Java-файлов в `../decompiled-standard/classes` и 4 528 в `../decompiled-standard/libs`, всего 10 047. Подготовлены проект IntelliJ и workspace VS Code для просмотра кода. Это восстановленный код для исследования; полная пересборка и локальный игровой запуск пока не подтверждены. Текущий результат и воспроизведение — [restoration-status.md](<E:/Stalcraft project/builds/stalcraft-pre-vk-2017-candidate/analysis/restoration-status.md>).

Диагностический запуск блокируется проверкой виртуальной среды; в памяти найдено сообщение «Sorry, this application cannot run under a Virtual Machine.» Полностью работоспособная распакованная DLL не получена. Один эксперимент с CPUID завершился ошибкой доступа к памяти; успешный обход не заявляется. Подробности, снимки и воспроизводимые скрипты — [dynamic-recovery.md](<E:/Stalcraft project/builds/stalcraft-pre-vk-2017-candidate/analysis/dynamic-recovery.md>). Разделы ниже описывают первичный файловый аудит; актуальное выполнение уточнено здесь.

## Что найдено

Это комплект клиентских файлов: `classes.jar`, `libs.jar`, `modassets`, звуки, конфиги и отдельные Java runtime x86/x64. Внешнего лаунчера или установщика в просмотренном комплекте нет. Инструкция предлагает поместить папку `stalcraft` в существующую папку игры, дождаться открытия ОФТ и играть.

Самая важная формулировка внутри `ПРОЧИТАЙ.txt`:

> Это не релиз ОФТ, а возможность ранней загрузки.

Файловые метки пакета относятся к 29.10.2017, что согласуется с предзагрузкой перед началом ОФТ 31.10.2017 по [официальной хронологии EXBO](https://support.exbo.net/ru/help-center/articles/16/17/220). Это сильное свидетельство периода и назначения пакета. Оно не является независимой проверкой издателя/исходного вложения VK и не удостоверяет неизменность файлов с 2017 года.

Пользователь указывает официальную группу как источник скачивания. В ходе файлового аудита принадлежность группы и точная внешняя ссылка вложения не перепроверялись. Пост: https://vk.com/wall-2677092_317761. Поэтому рабочая классификация — **клиентский пакет ранней загрузки ОФТ, вероятно конца октября 2017; источник указан пользователем, происхождение требует дальнейшего сопоставления**.

## Версии и структура

В `classes.jar!/fmlversion.properties`, `forgeversion.properties` и `version.json` обнаружены Minecraft 1.6.4, Forge 9.11.1.1345, FML 6.4.50, MCP 8.11 и профиль LaunchWrapper/FMLTweaker. `win32/java/release` и `win64/java/release` сообщают Java 9; совместимость с обычной Java 8/9 не проверялась.

ASM-метаданные в `mods/asmdata` содержат `com.stalcraft.StalcraftMod`, modid `STALCRAFT`, версию `1.1`, зависимость GloomyCore и client/server proxies. В `mcmod.info` GloomyCore маркирован `0.1.1_[1.6.4]`, а в ASM dump указан `2.4.47_[1.6.4]`. Разные источники метаданных/кэша расходятся; единственный точный номер версии всего клиента из них не устанавливается.

Техническая структура заметно отличается от текущей сборки Алекса с `stalker_client212.jar` и `ru.stalcraft`. У этого пакета нет обычного доступного набора исполняемых Java `.class` для прямой декомпиляции:

- `classes.jar`: 9 383 ZIP-записи, 361 запись `.class`, все нулевого размера; 6 975 payload-записей с 32-значными hex-именами;
- `libs.jar`: 8 447 ZIP-записей, 290 записей `.class`, все нулевого размера;
- полезные payload-данные не имеют Java magic `CAFEBABE`; простая распаковка выбранных образцов gzip/zlib/DEFLATE не раскрыла их.

Поэтому число пустых `.class` записей исходного inventory не означает число реальных классов. Последующий анализ восстановил защищённые hex-payload и нормализовал их opcodes; первичный файловый аудит выше описывает оригинальную упаковку.

Статическая проверка `win64/java/bin/server/jvm.dll` обнаружила секции `.vmp0`/`.vmp1`, строки VMProtect и 3 552 именованных экспорта с hex-именами. COFF timestamp — 28.10.2017 01:45:14 UTC. Последующая диагностика подтвердила встроенный декодер JAR/JIMAGE и custom JVM opcodes. `java.dll` необычно мала (7 680 байт), без export directory, с PDB-путём `EmptyDll1`. Нельзя считать этот комплект обычной неизменённой Java 9; запуск восстановленных классов на обычной Java требует отдельной проверки остальных runtime-зависимостей.

Подробный разбор и ограничения: [code-audit.md](<E:/Stalcraft project/builds/stalcraft-pre-vk-2017-candidate/analysis/code-audit.md>).
Native DLL: [code-native-loader.md](<E:/Stalcraft project/builds/stalcraft-pre-vk-2017-candidate/analysis/code-native-loader.md>).

## Карта, локации и ресурсы

В каталоге обнаружены 6 348 OGG, 1 765 MIC, 1 642 OL, 661 MCSA и 52 MCAL. Расширения обозначают разные ресурсные форматы; их количество не равно числу оружий, NPC или районов.

Типичного Minecraft-сохранения с регионами `.mca/.mcr` в предоставленном комплекте не найдено. Имеющиеся модели `.mcsa` не являются регионами мира. В `stalcraft/modassets/assets/pda` есть 223 тайла карты, `map.json`, `locations.json`, справочник локаций, safezones и переходы с координатами. `map.json` перечисляет 25 областей и 29 записей переходов; `locations.json` содержит 27 полигональных записей. Среди локаций — Болота, Чернобыль-4, Кордон, Свалка, Агропром, Янтарь, Бар, Радар, Лиманск, Янов, Затон и восточные районы.

Это позволяет изучать географию и карту интерфейса. Тайлы PDA не заменяют полноценные чанки мира, а список переходов не устанавливает устройство серверных инстансов.

Все 223 OL-тайла PDA удалось декодировать и собрать в обзорную сетку. На ней видны две раздельные области; серые клетки обозначают координаты, для которых нет тайла в комплекте. Оси показывают индексы тайлов, а не блоковые координаты Minecraft. Предпросмотр:

![Карта PDA из пакета ранней загрузки ОФТ](<E:/Stalcraft project/builds/stalcraft-pre-vk-2017-candidate/analysis/assets-pda-overview.png>)

Декодирование использует `sc-file==5.2.1`; все тайлы имеют размер 512×512, формат DXT1 и 10 mipmap-уровней. Формат и инструмент: [onejeuu/sc-file](https://github.com/onejeuu/sc-file). Ресурсы, координаты и ограничения подробно разобраны в [assets-audit.md](<E:/Stalcraft project/builds/stalcraft-pre-vk-2017-candidate/analysis/assets-audit.md>). Скрипт сохранён как `assets-pda-decode.py`, результаты — `assets-pda-stats.json` (223 успешно, ошибок нет).

Присутствие server-side proxy в метаданных не доказывает включение полноценного выделенного сервера. Работа singleplayer/offline пока не подтверждена. В справочном конфиге имеется `127.0.0.1:25545`; одного этого адреса недостаточно для вывода о встроенном сервере.

## Первое сравнение со сборкой Алекса

Ресурсы исходного `stalker_client212.jar` сопоставлены с `modassets` кандидата по точным путям `assets/...`, с дополнительной проверкой расширений PNG/MIC:

- исходный JAR содержит 1 583 ресурсные записи;
- найдено 24 пары совпавших путей;
- 4 звуковых файла полностью одинаковы по байтам: biological, chemical, machinegun_hit, radiation;
- у 5 изображений совпадает PNG-тело после первых восьми байтов сигнатуры, но отличаются расширение/сигнатура: empty armor, три размера backpack, transparent block.

Это подтверждает переиспользование отдельных ресурсов. Оно не доказывает идентичность кода или общий номер билда; ресурсные пространства и количество доступных данных сильно различаются. Не проводился поиск всех совпадений по содержимому при разных именах и не сравнивались все внешние ресурс-паки старой сборки.

Данные и метод: `alex-resource-comparison.json`. Скрипты исследования сохранены в `research/2016-2017-search-2026-10-03/audit-stalcraft-pre.py` и `compare-pre-resources.py`.

## Состояние дальнейшего исследования

Установлены назначение ранней загрузки, версия Minecraft/Forge, структура, исходные хеши и наличие карты PDA/ресурсов. Открытые вопросы: проверка издателя и исходного вложения, распаковка исполняемого кода, точная точка входа, совместимость Java, серверная часть и возможность локального мира. По этому статическому этапу не обещается самостоятельный запуск всей игры.
