# Проверенные API-границы защищённых helper

Результаты ограниченной интерпретации машинного кода в Unicorn. Функции не вызывались нативно; код Windows API не исполнялся. Ответы API подставлялись в эмуляторе. Для чтения страниц использовался только собственный процесс разрешённой диагностической копии Java с `-version`; исходные файлы и память процесса не изменялись. По окончании этот процесс завершался.

| Входной RVA JVM | Достигнутый API | Аргументы и результат |
| --- | --- | --- |
| `0x3ab210` | `NtClose` / `ZwClose` | Handle `0x1ee7c0de`; при синтетическом `STATUS_INVALID_HANDLE` helper вернулся с `RAX=0` за 26 инструкций. Независимая офлайн-трасса дала тот же результат за 24 инструкции с отдельным return-stub. |
| `0xf33409` | `GetCurrentThread` | При синтетическом псевдохэндле `-2` thunk вернулся с `RAX=-2` за 17 инструкций. |
| `0xf35d0a` | `ZwSetInformationThread` | `RCX=-2, RDX=0x11, R8=R9=0`; подставлен ответ success. Достигнута API-граница, но полноценный возврат thunk не подтверждён: трасса остановилась по конечному адресу после 20 инструкций. |

Первый вызов согласуется с проверкой недействительного handle и антиотладочным путём. Второй и третий соответствуют вызову `NtSetInformationThread(ThreadHideFromDebugger)` для текущего потока. Это объясняет видимые аргументы postamble шифра. В аргументах нет указателя или размера буфера класса, поэтому эти конкретные вызовы не дают оснований считать postamble дополнительным шифром. Вся функция и её исключительные пути этим не воспроизведены.

Артефакты: `live-protected-offset-helper.json`, `live-protected-current-thread-thunk.json`, `live-protected-hide-thread-thunk.json`; скрипт `emulate-live-protected-helper.py`. Независимый офлайн-скрипт и trace: `emulate-protected-helper.py/.json/.md`.
