# Статический аудит кода кандидата STALCRAFT из VK

Дата аудита: 2026-10-03. Проверялись только содержимое файлов и архивов; никакие JAR, EXE, DLL или bundled Java не запускались. Исходный каталог `E:\Stalcraft project\stalcraft_pre\stalcraft` не изменялся.

## Краткий результат

- **Minecraft/Forge:** с высокой уверенностью Minecraft 1.6.4 + MinecraftForge 9.11.1.1345; FML 6.4.50, MCP 8.11.
- **Мод STALCRAFT:** метаданные ASM указывают `com.stalcraft.StalcraftMod`, modid `STALCRAFT`, версия `1.1`, обязательную зависимость `GloomyCore`; есть клиентский и серверный proxy-классы.
- **Java:** дистрибутив содержит отдельные x86 и x64 runtime; их `java/release` указывает `JAVA_VERSION="9"`. Это точное свидетельство bundled runtime, но не доказывает, что игра не могла работать на другой совместимой Java.
- **Дата/статус публикации:** метки JAR — 29.10.2017 около 03:15. Переданный вместе с материалом README прямо сообщает: «Это не релиз ОФТ, а возможность ранней загрузки» и предлагает «Дождатся открытия ОФТ». Поэтому комплект позиционируется самой инструкцией как ранняя загрузка до релиза/открытия указанного этапа тестирования; это сильнее простой файловой датировки, но не устанавливает официальность источника или дату первоначальной разработки.
- **Критическое ограничение исследования:** обычные записи `.class` внутри `classes.jar` и `libs.jar` имеют нулевой размер. Значительная часть содержимого `classes.jar` — записи с 32-значными hex-именами без расширения и с данными, которые не являются стандартными Java class-файлами. Поэтому здесь нельзя напрямую восстановить точку входа приложения или проверить алгоритм старта мира. Возможны упаковка, шифрование или другая защита; точный механизм не установлен.
- **Сервер и offline:** метаданные подтверждают наличие server-side частей мода и FML-сетевого контракта. В проверенной структуре нет отдельного server JAR или launcher entry point. Наличие/работоспособность singleplayer или offline режима по доступному коду установить нельзя; закрытые payload-классы и возможная зависимость от онлайн-проверок оставляют вопрос открытым.
- **Официальность:** из содержимого и времени файлов нельзя вывести, что это официальный выпуск. VK URL и характеристика группы как официальной — сведения пользователя об источнике, отдельно не верифицированные этим аудитом.

## Доказательства

### Версии и технология

В `classes.jar!/version.json` указаны:

- `minecraftforge:9.11.1.1345`;
- `net.minecraft:launchwrapper:1.8`;
- аргумент `--tweakClass cpw.mods.fml.common.launcher.FMLTweaker`;
- обычный Minecraft argument template с `--username`, `--session`, `--version`, `--gameDir`, `--assetsDir`.

В `classes.jar!/fmlversion.properties`: FML 6.4.50, `fmlbuild.mcversion=1.6.4`, `fmlbuild.mcpversion=8.11`, branch 1.6.4, build 1345. В `forgeversion.properties`: Forge 9.11.1.1345. Это прямые внутренние идентификаторы версии, уверенность высокая.

Оба файла `win32/java/release` и `win64/java/release` сообщают `JAVA_VERSION="9"`; в каталогах находятся `bin/java.exe` и `bin/server/jvm.dll`. Они не запускались. Это доказывает наличие упакованных Java 9 runtime для двух архитектур, но не определяет единственную допустимую Java для байткода клиента.

### Мод и клиент-серверные признаки

`classes.jar!/mcmod.info` задаёт `modid=GloomyCore`, имя `S.T.A.L.K.E.R.`, версию `0.1.1_[1.6.4]`, URL `http://stalcraft.ru` и авторов GloomyFolken, Zero no Wing, Nerlied. Встроенное описание отображается как mojibake в исходной кодировке; само по себе оно не использовалось для вывода о происхождении.

Файлы `mods/asmdata/com.stalcraft.StalcraftMod.dump` и `mods/asmdata/gloomyfolken.mods.core.main.GloomyCore.dump` — сериализованные ASM-метаданные, не исполнялись. В первом видны:

- класс `com/stalcraft/StalcraftMod`;
- FML `@Mod`, имя STALCRAFT, версия `1.1`, modid `STALCRAFT`;
- зависимость `required-after:GloomyCore`;
- `@NetworkMod`;
- `@SidedProxy` со значениями `com.stalcraft.ServerProxy` и `com.stalcraft.ClientProxy`.

Во втором видны GloomyCore `2.4.47_[1.6.4]` и прокси `CommonProxy`/`ClientProxy`. Эти факты подтверждают серверно-клиентное разветвление кода Forge и сетевой мод STALCRAFT. Они **не** доказывают, что в архиве имеется автономный выделенный сервер или что сервер запускался без сети. Метаданные `version.json` относятся к клиентскому профилю запуска, а не к `minecraft_server.jar`.

В `modassets` находятся около 11 тысяч файлов и примерно 1.49 GB данных: конфигурации, локализация, PDA/map JSON, звуки/музыка, текстуры, предметы и ассеты STALCRAFT. Это указывает на богатый клиентский ресурсный пакет, но не раскрывает весь исполняемый код.

### Структура JAR и ограничение декомпиляции

ZIP inventory:

| Файл | Размер | Записей | Записей с суффиксом `.class` | Размер каждого `.class` |
|---|---:|---:|---:|---:|
| `classes.jar` | 30,058,147 байт | 9,383 | 361 | 0 байт |
| `libs.jar` | 30,116,661 байт | 8,447 | 290 | 0 байт |

В `classes.jar` также 6,975 записей без расширения; имена 6,975 таких записей состоят из 32 hex-символов, их полезные данные начинаются с различных байтов и не с Java magic `CAFEBABE`. Энтропия первых десяти крупнейших записей — 7.997–7.999 бит/байт. Прямая распаковка этих десяти записей gzip, zlib и raw DEFLATE не сработала; имена не совпали с MD5 видимых путей `.class`. Например, крупные записи `97a16932c69204ef02d32ed4789e87fa`, `5233d99579d766700abf91bfb1aac795`, `f5edc991da86029c8e78b12942099190` имеют сотни килобайт, но не стандартный заголовок class-файла. В `libs.jar` — 8,096 записей без расширения, при этом присутствуют нативные библиотеки LWJGL/OpenAL/JInput для разных платформ.

Вывод: привычная декомпиляция этих двух JAR по `.class`-файлам не даст код приложения. Неизвестные payload-классы не загружались, не исполнялись и не подвергались попыткам динамического распаковщика. Следующим безопасным шагом может быть разбор статического загрузчика/формата упаковки, если он обнаружится в полном дистрибутиве, либо сопоставление payload-хэшей с другими архивами.

### Дата и происхождение

Метаданные файловой системы показывают `classes.jar` 29.10.2017 03:15:04, `libs.jar` 29.10.2017 03:15:03; родительские каталоги получили метки в тот же день. Это подтверждает только timestamp имеющейся распаковки/архива; README независимо описывает содержимое как возможность ранней загрузки до релиза/открытия «ОФТ». Метки можно изменить при копировании и нельзя считать криптографическим доказательством происхождения.

Данные самого клиента содержат версию Forge и mod versions, но обнаруженные файлы не дают надёжного номера публичного релиза STALCRAFT или датированного changelog, привязанного к конкретной публикации. Наличие URL `stalcraft.ru` в `mcmod.info` не удостоверяет издателя JAR.

## Точка входа, сервер и offline: что установлено

**Установлено:** `version.json` предписывает запуск через LaunchWrapper/FMLTweaker; есть client assets и Minecraft 1.6.4/Forge-профиль; ASM-метаданные мода содержат `ClientProxy`, `ServerProxy` и сетевую регистрацию. Это не позволяет назвать главный Java-класс клиента: ожидаемые `.class` записи пусты, исполняемые payload'ы имеют нестандартный формат.

**Не найдено в осмотренном корне:** обычный `minecraft_server.jar`, скрипт запуска `.bat/.cmd/.ps1`, manifest с `Main-Class`, отдельный launcher EXE. Проверены корневые файлы и содержимое каталогов `classes.jar`, `libs.jar`, `assets`, `modassets`, `mods`, `win32`, `win64`. Это вывод только о текущей распакованной структуре; внешний лаунчер мог идти отдельно или отсутствовать в скачанном архиве.

**Offline/singleplayer:** по доступным данным нельзя подтвердить, что конкретная сборка разрешает singleplayer без авторизации/сервера, не делает сетевой запрос при старте и успешно создаёт мир offline. Исполняемый код недоступен, а возможные проверки онлайн не исследованы.
