# Наблюдение сбоя Windows — 04.10.2026

Пользователь сообщил, что Windows аварийно завершилась, и разрешил продолжить работу. Причинная связь с восстановлением STALCRAFT не установлена.

После перезагрузки прочитан System event1001 от 04.10.2026 00:28:35: bugcheck `0x0000001e`, параметры `0xffffffffc0000005, 0, 8, 0`. Event41 — 00:28:22; LastBootUpTime — 00:28:06. Event6008 сообщает о неожиданном завершении 03.10.2026 23:56:45; это поле нельзя автоматически принимать за точное время операции исследования.

Согласно [Microsoft](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/bug-check-0x1e--kmode-exception-not-handled), 0x1E обозначает необработанное исключение kernel mode, а 0xC0000005 — нарушение доступа. Конкретный драйвер, причина и процесс по одной записи не определяются.

Минидамп: `C:\Windows\Minidump\100426-29265-01.dmp`, размер 207872 байта, LastWriteTime00:28:30. Содержимое прочитать не удалось: Windows вернула PermissionError даже при запуске команды вне сломанного sandbox. Администраторские права не запрашивались; ACL и системные настройки не менялись.

Оперативная память по Win32_OperatingSystem после перезапуска: total33481664KiB, free21747564KiB (около20.7GiB). Это текущая свободная память, не доказательство её состояния во время сбоя.

После сообщения пользователя выполнялись только чтение событий/файлов и оформление результатов. Новая защищённая Java, игра и native-memory эксперименты не запускались. Восстановление всех class files и обе декомпиляции уже завершены с кодом0.

Обычный shell tool после перезагрузки не запускался: `helper_unknown_error: apply deny-read ACLs`. Для ограниченного чтения использован require_escalated, без исправления системных ACL. Эта неисправность инструмента сама по себе не устанавливает причину BSOD.
